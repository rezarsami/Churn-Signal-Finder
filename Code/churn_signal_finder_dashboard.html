Product Operations Analyst · Portfolio Case Study

A churn signal was hiding inside one plan-and-region pocket. This console mines it out, tests that it's real, and sizes the revenue at stake.

Starting from a raw 12K-row export with duplicates, null regions, and inconsistent plan labels, I built a repeatable cleaning pipeline, then tested churn across every plan × region cell. Only pockets that are both statistically distinguishable from baseline and large enough to act on get flagged — 16 cells tested, 1 flagged.

Test every cell, flag only what's real

Each plan × region cell is compared against the rest of the base. Flagging one cell out of sixteen — not eyeballing a heatmap — is what keeps this honest.

Churn rate · plan × region

The pocket surfaced after Sep 2024 and tracks with a jump in support tickets and a drop in CSAT — the signature of a regional product defect, not a pricing problem. It clears a two-proportion test after correcting for all sixteen comparisons.

Recommendation → Route this cohort to a targeted save-play and open a defect investigation with Eng on the APAC scheduling sync. At an assumed save rate, that's the recoverable revenue shown above.

05

How it was built

The pipeline is reproducible — rerunning it on next month's export regenerates every view above.
EXTRACT
Raw export
12,080 rows ingested with pandas from the product DB dump.
CLEAN
Normalize
Dropped 80 dupes, filled null regions → Unknown, fixed plan casing, imputed engagement medians.
MINE + TEST
Segment
Tested churn in all 16 plan × region cells vs. baseline; flagged only the significant, high-magnitude one.
SHIP
Dashboard
Exported to JSON, rendered as this self-contained interactive console. Rerun the pipeline and every number updates.
